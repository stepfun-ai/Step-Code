# StepCode 拓展包与市场展示规范（V1 草案）

本规范面向 StepCode 拓展市场维护者和拓展适配开发者，定义插件、独立技能和连接器的交付要求，保证来源可追溯、展示一致、资源完整和接入明确。任意会话接收一批待分类拓展后的执行步骤、注册边界、批次记录和续办模板见[批量拓展分类、规范化与市场注册流程](extension-onboarding-standard.md)。

编制日期：2026-11-09。依据当前工作区代码核实，不代表所有规则已经由程序自动执行。

## 1. 适用范围与要求等级

- **现有运行要求**：当前解析器、安装器或打包流程已经要求满足的条件。
- **上架强制标准**：本草案新增的交付与审核要求，部分需要人工检查或后续补充自动门禁。
- **建议**：推荐的命名、文案与视觉约定，不应被误认为现有运行时校验。

本规范主要覆盖 Web 与 Desktop 的拓展市场，不将其他平台的插件、技能或 MCP 配置兼容性视为默认成立。

## 2. 三类拓展的边界

| 上架类型 | 判定标准 | 运行入口或接入方式 |
| --- | --- | --- |
| 插件 | 一个可安装功能包，可以包含技能、命令、连接器等组件 | 原生 `step.plugin.json` |
| 独立技能 | 一套独立任务执行指令，可附带脚本、参考资料和素材 | 根目录 `SKILL.md` |
| 连接器 | 通过 MCP 协议提供工具的本地程序或远程服务 | 本地启动配置或远程 MCP 地址 |

上架分类必须依据 StepCode 中实际可用的形态，不得直接照搬来源市场标签。

- 插件中的技能不自动成为独立技能商品。
- 单独上架插件内技能，必须重新核查依赖、再分发权限并独立验收。
- 技能依赖 MCP、外部 CLI 或其他技能时，必须声明前置条件，不能假定原平台环境存在。
- 一个包不得只有商品介绍而没有可用能力。

## 3. 共用市场展示规范

### 3.1 展示数据来源

当前市场展示由[市场目录](../apps/web/client/src/features/market/catalog/catalog.json)和前端资源映射驱动，不会仅凭拓展包内的名称与图片自动生成完整商品。

市场目录与实际分发资源必须一致。字段类型及映射见[市场数据模块](../apps/web/client/src/features/market/extension-market-data.ts)。

### 3.2 上架信息与必填规则

| 信息 | 标准 |
| --- | --- |
| 商品 ID | 全市场唯一，发布后稳定；建议采用 `类型-发布者__名称` |
| 运行标识 | 插件对应 manifest `id`；技能对应 frontmatter `name`；连接器对应固定 `serverName` |
| 名称 | 简短、可识别，不含未经证实的“最强”“全能”“官方认证”等宣传 |
| 一句话介绍 | 已有介绍默认原样保留；确需翻译、精简、改写或补充时，先提交前后对照并取得用户确认，再写入；候选介绍用一句话说清用途，中文建议 20～80 字 |
| 版本 | 必须确定；建议使用语义化版本，适配版本与上游版本分别记录 |
| 发布者 | 明确上游作者与 StepCode 适配维护者，不得混淆 |
| 分类 | 至少一个主要用途分类，可补充其他分类，不得无依据全选 |
| Logo | 可选；提供时须获得授权并正确引用本地资源，未提供时使用类型默认图标，不阻止上架 |
| 详情说明 | 说明功能、前置条件、用法、限制和授权要求 |
| 组件清单 | 插件列出实际交付的技能、命令和连接器；数量与包内容一致 |
| 原项目来源 | 记录原项目地址、获取渠道、固定版本或提交号 |
| 许可证与分发依据 | 记录许可文件、必要声明和允许当前分发方式的依据 |
| 适用环境 | 记录已经验证的系统、运行时和外部应用要求 |

新增的来源、适用环境等管理信息，可先记录在接入说明中。需要作为独立 UI 字段展示时，必须同步扩展目录结构、映射与页面；仅向 JSON 添加字段不代表页面会显示。

下载量没有真实统计时保持未知，不得填入模拟数据。本市场的“官方”仅指 StepFun 官方，不扩展到腾讯、ProcessOn 等第三方原厂。官方归属须由项目负责人明确确认或有可核实的 StepFun 维护依据；适配者不能仅因完成移植、引用官方资料或名称含 StepFun 而获得标识。

经确认的 StepFun 官方技能使用现有 `selfMade: true` 元数据，在列表与详情显示“StepFun 官方”徽标，并在市场介绍前增加“StepFun 官方技能：”前缀，原介绍正文保留。技能原文、运行标识及权限不因此改变；徽标不代表功能、安全或再分发验收已通过。重打包必须保留已经确认的介绍及官方元数据，不用上游描述覆盖。

### 3.2.1 中文化与一句话用途说明

已有介绍默认原样保留，不因英文、长度、风格或批量统一措辞而自动修改。介绍的意义优先于语言转换：先判断是否需要修改，确需修改时再核实能力并提出候选文案。本规则适用于插件、独立技能和连接器的列表介绍及详情页摘要。

| 原介绍情况 | 处理方式 |
| --- | --- |
| 英文介绍已经明确用途 | 默认保留；需要中文化时提出译文，保留品牌名和技术名称，用户确认后才替换 |
| 中文介绍已经明确用途 | 默认原样保留，不自动精简或润色 |
| 只有名称、CLI 名称、组件数量、宣传词或泛化套话 | 核实能力后提出一句用途说明，说明修改原因，用户确认后才替换 |
| 原介绍包含当前适配未支持的能力 | 标记能力不一致并暂停该项放行，提出修订与限制说明，用户确认后才写入 |
| 未提供介绍 | 根据已核实能力起草补充文案，用户确认后才写入 |
| 无法核实用途 | 标记待核实，不仅凭名称猜测，也不填入虚构介绍后注册 |

建议句式为“用于／帮助 + 具体任务 + 必要场景或结果”，以能独立读懂为准，不强制每句以“该插件”“该技能”“该连接器”开头。组件数量放在组件区，不代替用途。

例如，已有英文介绍说明在 Cloudflare 上构建、测试和部署应用，可译为“帮助在 Cloudflare 上构建、测试和部署应用，提供平台操作指引与 MCP 工具支持。”这只示范如何保留原介绍含义，不代表该拓展已经在 StepCode 中完成接入或验收。

“钉钉 Workspace CLI（dws）与 17 个办公技能”只说明组成，仍需核实支持哪些办公任务，再写出这些任务的用途；不能仅因属于办公分类而补写未经核实的能力。

纯英文资料可以起草面向使用者的介绍和必要使用说明译文，取得用户确认后再替换，不得改变执行步骤、触发语义、权限要求或能力边界。技术标识、商品 ID、命令、参数、环境变量名、配置键、包名和路径保持原样；许可文件及必要署名保留原件，译文不代替许可原件。

保存原介绍、候选介绍、修改原因、能力证据及用户确认结果到批次记录。仅同步已确认文案对应的市场目录、详情摘要和相关分发文档；不修改其他条目。有语义变化的 SKILL.md 需要重新验收，并更新对应版本、哈希及 payload。不能仅因原文使用英文就声称内容不合格，不能为了达到建议字数而擅自删改已有介绍。

### 3.2.2 文案修改确认门禁

先检查并提交清单，再修改。每个候选项至少展示商品 ID、名称、原介绍、建议介绍、修改原因和能力证据；明确区分“保留”“建议翻译”“建议改写”“建议补充”“待核实”。已有介绍合格的条目列为保留，不进入修改批次。

用户可以逐项确认，或明确批准列出的整批候选项。一般性的“按规范改写”不替代本门禁；不得将沉默、会话中断或未明确范围的回复视为全部通过。未确认项保持原文，不进入正式 catalog、payload 或分发文档；候选译文仅保存到独立审核记录中。

确认绑定到展示过的原文和候选文案。原文、候选文案或能力范围发生变化时重新确认；跨会话续办必须读取实际确认记录，不能凭执行者记忆推定同意。无法核实能力的条目即使确认文案也不能绕过功能与许可验收。

### 3.3 可选 Logo 与默认图标

Logo 可选。未提供 Logo 时省略市场目录中的 `logo` 字段，使用统一类型默认图标，不要求创建图标文件，也不因缺少 Logo 阻止上架。

| 类型 | 默认图标 | 图标名称 |
| --- | --- | --- |
| 插件 | 调节器 | `sliders` |
| 独立技能 | 魔法棒 | `wand` |
| 连接器 | 地球 | `globe` |
| 已知为本地 stdio 的连接器 | 终端 | `terminal` |

默认图标应覆盖列表与详情，保持统一容器尺寸、背景和留白，适配浅色与深色主题。名称与介绍照常显示，不使用空白区域、破损图片或未经授权的品牌图作为替代。连接器类型未知时使用地球图标；已知为 stdio 时使用终端图标。

提供 Logo 时，必须满足：

- 格式为 PNG、WebP，或经过净化的 SVG。
- 位图建议 512 × 512，正方形，透明或统一背景。
- 文件建议不超过 200 KB。
- 四周留白，在浅色、深色背景下均可辨认。
- SVG 禁止脚本、事件处理和外部资源引用。
- 不得使用未经授权的品牌图标或冒充官方。
- 包内保留图标资源；市场图标同时加入现有 `catalog/logos/` 资源目录。
- 市场目录中的 `logo` 字段必须匹配实际文件名，构建后验证可显示。

声明 Logo 但文件缺失、引用错误或图片无法加载时，应修复资源或移除声明并使用默认图标，不能当作合格 Logo 放行。

当前加载逻辑见[市场数据模块](../apps/web/client/src/features/market/extension-market-data.ts)。[目录列表](../apps/web/client/src/features/market/ExtensionMarketPage.tsx)和[目录详情页](../apps/web/client/src/features/market/ExtensionMarketDetail.tsx)已使用插件调节器、技能魔法棒，以及按传输类型选择的连接器终端或地球默认图标；[已配置连接器列表](../apps/web/client/src/features/market/ConnectorMarketList.tsx)和[详情页](../apps/web/client/src/features/market/ConnectorMarketDetail.tsx)也按传输类型使用终端或地球图标。2026-11-09 浏览器复核80个市场条目，68个已有Logo正常加载，12个缺Logo技能的列表与详情默认图标均正常；该结果仅证明图标展示，不代表全部规范或功能已验收。

### 3.4 共用交付资料

| 文件或资料 | 要求 |
| --- | --- |
| 运行入口 | 按三类拓展分别定义 |
| 使用说明 | 插件、连接器采用 README；技能可以由 SKILL.md 承担 |
| 许可证材料 | 保留上游 LICENSE 或等效许可文件；按许可要求附 NOTICE，必要时附书面授权依据 |
| 接入说明 | 记录来源、适配改动、依赖、配置、权限和限制；建议统一命名为 `接入说明.md` |
| Logo | 可选；提供时包内保留并同步市场资源目录，未提供时使用类型默认图标 |
| 验收记录 | 保存在维护资料中，不强制进入运行包；内容要求见配套流程规范 |

不是所有资料都是运行时入口；运行必需与上架审核必需应分别检查。不得为第三方代码自行指定许可证。公开可下载不等于允许商业使用或文件再分发。

### 3.5 文件与安全边界

禁止分发：

- 真实账号、令牌、密码、私钥及其他凭据。
- 开发者机器的绝对路径和其他产品的私有配置。
- 无关仓库、缓存、`.git`、`node_modules` 和无关历史文件。
- 路径穿越、符号链接、重复文件及大小写冲突路径。
- 要求关闭 StepCode 权限检查才能运行的适配实现。
- 安装阶段擅自修改其他产品配置、全局 Shell 配置或用户业务文件的逻辑。

运行文件与文档使用包内相对路径；执行或引用的资源必须完整交付。外部依赖必须在接入说明中明确声明，不得伪装成已随包提供。

## 4. 插件规范

### 4.1 必需文件与组件

| 文件 | 要求 |
| --- | --- |
| 根目录 `step.plugin.json` | 上架强制采用 StepCode 原生 manifest |
| README | 上架强制，承担商品详情和使用说明 |
| 许可证材料、接入说明 | 按共用标准交付 |
| Logo | 可选；未提供时使用类型默认图标，提供时按共用标准交付 |
| `skills` 声明资源 | 有声明就必须完整交付，各技能具有有效 SKILL.md |
| `commands` 声明资源 | 有声明就必须存在对应 Markdown 命令文件 |
| MCP 声明文件 | 使用 `mcpServers` 文件引用时必须随包存在且可解析 |
| 脚本、参考资料、素材及运行依赖文件 | 被执行或引用时必须完整交付 |

当前安装器也支持已有的 Claude 兼容声明入口，但本草案要求精选上架包规范化为原生声明，避免依赖隐式转换。

manifest 的现有字段定义见[插件声明实现](../packages/coding-agent/src/step/plugins.ts)。运行时要求有效 `id`；本草案将 `name`、`description`、`version` 提升为上架必填。

下面仅展示声明结构，不是可直接安装的完整包；必须同时提供实际技能资源：

```json
{
  "id": "publisher-toolkit",
  "name": "工具包名称",
  "description": "用于某类工作场景的具体功能说明",
  "version": "1.0.0",
  "skills": ["skills"]
}
```

### 4.2 功能与依赖约束

- 至少一个组件在 StepCode 中实际可用。
- 声明路径必须位于包内，不得指向原下载目录。
- 外部 CLI 记录包名、固定版本、准备方法和首次授权步骤。
- `provision` 不是任意安装脚本执行入口。不支持的自动准备配方必须给出手动准备说明。
- 原平台的 Agent、Hook 或入口脚本不能仅因被复制而宣称获得相同能力。
- `entry`、`agents` 或额外运行文件必须单独核查打包与加载链路。

当前[插件打包脚本](../apps/web/scripts/package-plugin-market.mjs)主要收集技能、命令、MCP 声明、根级关联资源和许可声明，没有完整覆盖所有 manifest 能力。当前[安装器](../packages/coding-agent/src/step/plugin-install.ts)也明确提示 entry 和 agent 定义不由该安装器执行；不得将这一提示误解为已完成运行验收。

依赖准备与授权边界见[插件 CLI 准备说明](plugin-cli-preparation.md)。

### 4.3 当前包体限制

- 上传 ZIP 不超过 32 MiB。
- 解压内容不超过 64 MiB。
- 文件条目不超过 6000。
- 一个包只有一个插件根目录，可以是扁平目录或一个包装目录。

安装检查见[插件安装器](../packages/coding-agent/src/step/plugin-install.ts)及[插件市场安装说明](plugin-market.md)。复制成功不等于组件可用。

## 5. 独立技能规范

### 5.1 必需文件

| 文件 | 要求 |
| --- | --- |
| 根目录 `SKILL.md` | 现有运行必需，唯一主入口 |
| 许可证材料、接入说明 | 按共用标准交付 |
| Logo | 可选；未提供时使用类型默认图标，提供时按共用标准交付 |
| 脚本、参考资料、素材 | SKILL.md 引用或执行时必须完整交付 |
| 依赖声明及可复现版本信息 | 包含代码且依赖第三方库时必需，按实际语言和生态选择文件格式 |

纯指令技能不强制添加空脚本目录。独立技能不通过安装 SKILL.md 自动注册 MCP 服务。

### 5.2 Frontmatter

当前运行时要求有效 YAML frontmatter，其中：

- `name` 是不含空格和路径分隔符的可移植名称。
- `description` 为非空字符串。
- 根 SKILL.md 不超过 512 KiB。

本草案进一步要求 `name` 使用小写 kebab-case，并记录版本与许可。以下为字段示意，许可占位值必须替换为真实许可，不能原样交付：

```yaml
---
name: document-helper
description: 整理文档内容并输出结构化结果，适用于文档汇总和检查任务。
version: 1.0.0
license: 实际许可证标识
---
```

现有校验见[技能安装器](../packages/coding-agent/src/step/skill-install.ts)。

### 5.3 SKILL.md 正文最低要求

1. 触发条件：何时应该使用，何时不应该使用。
2. 输入要求：需要提供的内容、文件及参数。
3. 前置条件：运行时、CLI、MCP、账号和权限。
4. 执行步骤：可执行的具体操作。
5. 输出约定：结果格式、输出位置和成功标志。
6. 异常处理：缺依赖、授权失败、输入错误时的处理方式。
7. 操作边界：需要确认的操作和禁止自动执行的操作。

移植时替换原平台专有工具、路径与技能调用方式。无法提供等价能力时必须明确限制，不能用指令声称工具已经存在。

### 5.4 当前包体限制

- 上传不超过 32 MiB。
- 解压内容不超过 128 MiB。
- 文件条目不超过 16000。
- 提供一个根 SKILL.md，所有交付资源位于技能根目录之内。

## 6. 连接器规范

### 6.1 交付形态

- 远程服务型：交付真实 MCP 端点和认证配置。
- 本地程序型：交付可复现启动方式，必要时附带本地程序或上游依赖信息。

不统一要求连接器携带服务端源码、`package.json` 或 Python 依赖文件。所需运行环境和文件取决于真实实现；仅提供远程接入模板时不能宣称自行分发服务端实现。

### 6.2 必需文件与资料

| 内容 | 要求 |
| --- | --- |
| 接入配置模板 | 强制，包含固定 `serverName` 和 StepCode 可识别配置；当前由市场目录中的 connection 信息承载 |
| README | 强制，说明能力、接入步骤、认证、环境和成功标志 |
| 许可证或服务使用依据 | 本地分发核查软件许可；远程接入核查服务使用条件 |
| 来源、接入说明 | 按共用标准交付 |
| Logo | 可选；未提供时使用类型默认图标，提供时按共用标准交付 |
| 本地程序及依赖声明 | 自行分发本地实现时必需 |
| 工具说明 | 至少说明主要工具、输入、输出和读写副作用 |

当前模板来源见[连接器模板脚本](../apps/web/scripts/package-connector-templates.mjs)。不新增一个未被加载器识别的配置文件，并误称它为运行入口。

### 6.3 配置要求

依据[当前 MCP 配置解析器](../packages/coding-agent/src/step/mcp-settings-secrets.ts)：

- 本地服务使用 `command`，按需提供 `args`、`env`、`cwd`。
- 远程服务使用 `url`，按需提供 OAuth 或环境变量认证引用。
- `command` 与 `url` 必须二选一。
- 官网地址、源码地址和文档地址不能代替 MCP 服务端点。
- 本地依赖使用固定版本，不能以 `latest` 为正式验收基线。
- 路径占位符在保存或运行前填写；不能将占位符当真实路径。
- 模板不包含真实密钥；说明凭据的配置方式和最小必要权限。
- stdio 服务的协议输出不得混入普通日志，普通日志输出到 stderr。
- 远程服务记录费用、配额和使用限制；无法核实的信息明确标记待核实。

### 6.4 可用性要求

必须分别验证：依赖或服务准备完成、认证完成或无需认证、MCP 初始化成功、工具发现成功、代表性工具调用成功。

模板能打开、配置能保存、端口能连接均不能作为最终业务可用证据。平台支持范围只能按实测公布。
