# 任务计划隔离与显式续做

用户确认：新计划单独计数，旧计划保留历史，只有明确续做时才恢复；不按用户消息或 agent turn 自动清空任务。

## 实现边界

- 保留四个 task 工具。`task_create` 增加可选 `newPlan` 标题：仅在不同任务的第一项上使用，原清单存为历史，后续创建默认追加当前计划。
- `task_list({includeHistory:true})` 只读列出计划 ID、标题、当前标记及完成/总数；默认仍返回当前计划任务。
- `task_update({resumePlanId})` 为独立切换操作，不与 taskId 或任务修改字段混用。只恢复指定历史计划，同时保存切换前的计划。历史任务不能直接更新或成为当前计划依赖。
- 当前任务 Map 仍是唯一活动状态；计划历史和活动计划标识跟随既有 step-tasks 会话快照保存。旧快照作为一份计划恢复，不猜测既有混合任务的语义分界。ID 继续使用会话级单调编号。
- 新建/更新工具走已有 sequential 调度能力；不新建工具、事件总线、定时器或持久化服务。不改 Markdown 规划模式或 Updated Plan 的样式。
- 系统提示词说明何时新建、何时续做；不会通过关键词、轮次或自动完成推断计划边界。

| Step | Tool | Expectation | Rollback |

| 增加计划切换及历史快照 | apply_patch | 新清单仅有 5 项；旧清单不被删除或自动重新激活 | 反向撤销本轮 tasks 增量，不改用户会话文件 |
| 补齐模型指引与文档 | apply_patch | 新任务首次创建带 newPlan；明确续做才使用 resumePlanId | 撤销本轮提示词/文档增量 |
| 回归恢复与并发边界 | 指定任务、提示词、集成测试；npm run check | 多轮保留、历史不可变、切换/压缩/分支恢复正确；不跨计划串状态 | 修正本轮实现 |

不删除会话历史、不提交、不构建、不调用真实模型。不执行数据迁移脚本；恢复逻辑只读取现有会话数据，后续写入仍走既有 appendEntry。

## 完成与验证

- RED：修改前四项定向回归失败，其中用户给出的旧三项加新五项原样复现为 `Updated Plan (1/8)`，而不是期望的 `0/5`。
- GREEN：任务、系统提示词、规划模式、能力注册四个产品测试文件 136 项通过；实际 TUI 组件测试 9 项通过，共 145 项。
- 覆盖新计划隔离、显式来回续做、历史只读、已归档任务与跨计划依赖拒绝、非法切换不修改状态、跨轮保留、空计划、重复续做、元数据及依赖保留、压缩/重载/分支恢复、单调 ID、历史快照不漂移。
- `npm run check` 通过，包含类型和结构机械检查；`git diff --check` 通过。npm 仍提示项目已有的两项 workspace 配置警告，未修改依赖或配置。
- 未运行完整测试、构建、真实模型或付费调用；工具契约及模型提示词已验证，但未宣称真实模型一定正确判断每一次语义上的新任务。
- 旧无计划标识的混合清单作为一份历史恢复，不自动猜测拆分。后续明确的新计划使用独立边界。
